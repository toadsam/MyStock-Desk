# 숫자 계산 규칙

화면에 뜨는 숫자가 어디서 어떻게 나오는지 적었습니다. "이 숫자 맞아?"라는 질문에 이 문서만 보고 답할 수 있게 하는 것이 목표입니다.

원칙은 세 가지입니다.

1. **저장하지 않고 매번 계산합니다.** 하루 예산, 남은 생활비, 투자 가능 금액, 목표 달성률은 DB에 없습니다. 요청이 올 때마다 기록(소비, 예산, 거래)에서 다시 셉니다. 저장해 두면 소비 하나를 지울 때 같이 고쳐야 할 곳이 생기고, 언젠가 하나를 빠뜨립니다.
2. **기록이 없으면 0입니다.** 예산을 정하지 않은 사람에게 예시 숫자를 채워 넣지 않습니다. 0이거나 "예산 정하기" 안내가 뜹니다.
3. **"오늘"은 서울 시간입니다.** `ClockConfig`의 `Clock` 하나를 통해 날짜를 얻습니다. 테스트에서는 이 시계를 고정해 날짜에 따라 결과가 바뀌지 않게 합니다.

아래 예시 숫자는 데모 계정(`investor@stockflow.com`)으로 2026-10-12(월)에 실제로 받은 값입니다.

---

## 1. 오늘 더 써도 되는 돈

홈의 큰 숫자입니다. [`TodayService`](../backend/src/main/java/com/stockflow/dashboard/service/TodayService.java), API는 `GET /api/dashboard/today`.

```
남은 날수        = 이번 달 일수 − 오늘 날짜 + 1                (오늘 포함)
하루 예산        = ⌊ (생활비 예산 − 어제까지 쓴 돈) ÷ 남은 날수 ⌋₁₀₀
오늘 더 써도 되는 돈 = max(하루 예산 − 오늘 쓴 돈, 0)
오늘 넘친 돈      = max(오늘 쓴 돈 − 하루 예산, 0)
남은 생활비       = max(생활비 예산 − 이번 달 쓴 돈 전부, 0)
기준 하루 예산     = ⌊ 생활비 예산 ÷ 이번 달 일수 ⌋₁₀₀
```

`⌊ ⌋₁₀₀`은 100원 단위 내림입니다.

| | 값 |
|---|---|
| 생활비 예산 (`monthly_budget.living_budget_amount`) | 550,000원 |
| 어제(10/11)까지 쓴 돈 | 155,900원 |
| 남은 날수 | 31 − 12 + 1 = **20일** |
| 하루 예산 | (550,000 − 155,900) ÷ 20 = 19,705 → **19,700원** |
| 오늘 쓴 돈 | 학생식당 3,800 + 학교 앞 카페 3,000 = 6,800원 |
| **오늘 더 써도 되는 돈** | 19,700 − 6,800 = **12,900원** |
| 남은 생활비 | 550,000 − 155,900 − 6,800 = 387,300원 |
| 기준 하루 예산 | 550,000 ÷ 31 = 17,741 → 17,700원 |

**왜 이렇게 나누나.** 처음부터 "550,000 ÷ 31 = 하루 17,700원"으로 고정하면, 어제 많이 쓴 사람에게도 오늘 17,700원을 써도 된다고 말하게 됩니다. 남은 돈을 남은 날로 다시 나누면 어제 아낀 돈은 오늘부터 조금씩 늘어나고, 어제 넘친 돈은 조금씩 줄어듭니다. 홈 위쪽 벨루가 말풍선이 하는 말이 이것입니다.

**오늘 쓴 돈은 오늘의 하루 예산을 바꾸지 않습니다.** 하루 예산은 "어제까지" 쓴 돈으로 정합니다. 오늘 쓴 돈까지 넣으면 커피 한 잔을 살 때마다 하루 예산이 같이 줄어서, 남은 돈이 두 번 깎이는 것처럼 보입니다.

**100원 단위로 내리는 이유.** 19,705원은 정확하지만 읽는 사람에게 의미가 없습니다. 올리지 않고 내리는 것은 예산을 넘기지 않는 쪽으로 틀리기 위해서입니다.

**예산이 없으면** `budgetSet: false`, 하루 예산 0입니다. 그날 쓴 돈은 전부 "넘친 돈"으로 잡히고, 화면은 숫자 대신 예산을 정하라는 안내를 띄웁니다.

**이번 주 7일**은 월요일부터 일요일까지 날짜별 소비 합계입니다. 오늘 뒤의 날은 `future: true`로 표시해 빈 잔으로 그립니다.

## 2. 이번 달 자산 요약

[`AssetService.getSummary()`](../backend/src/main/java/com/stockflow/asset/service/AssetService.java), API는 `GET /api/assets/summary`.

```
계좌 잔액     = Σ 계좌 잔액                   (총자산에 포함한다고 표시한 계좌만)
투자 자산     = portfolio.total_asset
총자산       = 계좌 잔액 + 투자 자산
남은 생활비    = max(생활비 예산 − 이번 달 소비 합계, 0)
투자 가능 금액  = max(이번 달 투자 계획 − 이번 달 매수 금액 합계, 0)
저축률       = 저축 계획 ÷ 수입 × 100        (수입이 0이면 0)
```

**투자 가능 금액에는 남은 생활비를 더하지 않습니다.** 예전 식은 남은 생활비까지 더해서, 이번 달 밥값을 투자해도 된다고 말하고 있었습니다. 지금은 사용자가 예산에 직접 적은 "이번 달 투자 계획"에서 이번 달에 이미 매수한 금액(`investment_transaction`의 `BUY` 중 이번 달 거래의 `total_amount`)만 뺍니다. 데모 계정은 계획 30,000원, 이번 달 매수 0원이라 30,000원입니다.

## 3. 소비 분석

[`ExpenseService.getMonthlySummary()`](../backend/src/main/java/com/stockflow/expense/service/ExpenseService.java), API는 `GET /api/expenses/monthly-summary`.

```
이번 달 합계         = Σ 이번 달 소비
지난달 비교 금액       = Σ 지난달 1일 ~ 지난달 같은 날짜의 소비      (이번 달이 진행 중일 때)
증감률              = (이번 달 합계 − 지난달 비교 금액) ÷ 지난달 비교 금액 × 100
일평균              = 이번 달 합계 ÷ 지난 날수                (진행 중이면 오늘 날짜, 끝난 달이면 그 달 일수)
카테고리 비중         = 카테고리 합계 ÷ 이번 달 합계 × 100
카테고리 건당 평균      = 카테고리 합계 ÷ 건수
```

**지난달 한 달 전체가 아니라 같은 날짜까지와 비교합니다.** 12일까지 쓴 돈을 지난달 31일치와 비교하면 매달 초에는 늘 "소비가 줄었다"가 됩니다. 이번 달이 진행 중이면 지난달도 같은 날짜(지난달이 더 짧으면 그 달 말일)까지만 더합니다. 일평균도 같은 이유로 30이 아니라 지난 날수로 나눕니다.

**TOP 3**는 이번 달 금액이 큰 카테고리 세 곳입니다. 각 항목의 `ratio`는 그 카테고리가 이번 달 소비에서 차지하는 비율(%)입니다.

**6개월 추이**는 이번 달을 포함한 최근 여섯 달의 소비 합계와, 그 달에 정해 둔 생활비 예산을 나란히 줍니다. 예산을 정하지 않은 달은 0입니다.

## 4. 목표

[`SavingGoalDto.of()`](../backend/src/main/java/com/stockflow/goal/dto/SavingGoalDto.java), [`GoalService`](../backend/src/main/java/com/stockflow/goal/service/GoalService.java).

```
남은 금액         = max(목표 금액 − 모은 금액, 0)
달성률           = min(모은 금액 ÷ 목표 금액 × 100, 100)      (소수 첫째 자리)
남은 날수         = max(목표일 − 오늘, 0)
하루에 모아야 할 돈   = ⌈ 남은 금액 ÷ 남은 날수 ⌉                 (남은 날수가 0이면 남은 금액 전부)
메인 목표         = 진행 중(ACTIVE)인 목표 중 남은 날수가 가장 적은 것
```

데모 계정의 메인 목표 "다음 달까지 30만원 모으기"는 112,000 / 300,000 = **37.3%**, 남은 금액 188,000원, 남은 날수 16일, 하루에 188,000 ÷ 16 = **11,750원**입니다.

**하루에 모아야 할 돈은 올립니다.** 내리면 그대로 모아도 목표일에 몇 원이 모자랍니다.

**메인 목표 하나가 여러 화면의 기준입니다.** 홈의 목표 카드, 절약 시뮬레이션, 코치가 모두 이 목표로 말합니다. 우선순위(`priority`) 필드는 저장만 하고 메인 목표를 고를 때는 쓰지 않습니다.

**완료.** 목표를 `COMPLETED`로 바꾸면 화면에 축하 화면(꽃가루와 벨루가)이 한 번 뜹니다. 앱에서 꽃가루가 터지는 곳은 여기 하나뿐입니다.

## 5. 추천 행동과 절약 시뮬레이션

**추천 행동** (`GET /api/goals/actions`): 이번 달 가장 많이 쓴 카테고리 세 곳을 각각 20% 줄였을 때 아끼는 금액입니다. `impactScore`는 그 카테고리의 이번 달 소비 비중(%)입니다. 예전에는 비중을 10으로 나눠 음수를 붙인 값을 "목표 영향"이라고 내보냈는데, 아무 근거가 없는 숫자라 지웠습니다.

**절약 시뮬레이션** (`POST /api/expenses/saving-simulation`):

```
카테고리별 절약액 = 카테고리 이번 달 합계 × 줄일 비율 ÷ 100      (원 단위 반올림)
총 절약액       = Σ 카테고리별 절약액 + 고정 저축액
예상 달성률      = min((메인 목표의 모은 금액 + 총 절약액) ÷ 목표 금액 × 100, 100)
```

아낀 돈이 그대로 메인 목표로 들어간다고 가정합니다. 화면은 이번 달 실제 TOP 3 카테고리를 슬라이더로 보여 주고, 사용자가 고른 비율을 보냅니다.

## 6. 투자

[`Holding`](../backend/src/main/java/com/stockflow/portfolio/entity/Holding.java), [`TransactionService`](../backend/src/main/java/com/stockflow/transaction/service/TransactionService.java).

```
매수 후 평균단가  = (기존 평균단가 × 기존 수량 + 매수 단가 × 매수 수량) ÷ (기존 수량 + 매수 수량)
매도           = 수량만 줄이고 평균단가는 그대로
평가금액        = 현재가 × 수량
손익           = 평가금액 − 평균단가 × 수량
수익률          = 손익 ÷ (평균단가 × 수량) × 100
비중           = 평가금액 ÷ 총 투자자산 × 100
```

**거래를 고치면 처음부터 다시 계산합니다.** 거래를 등록, 수정, 삭제할 때마다 보유 종목을 전부 지우고, 거래 기록을 날짜순으로 처음부터 다시 재생합니다. 5월 매수 단가를 고쳤을 때 그 뒤에 쌓인 평균단가가 조용히 틀어지는 일을 막기 위해서입니다. 대신 거래 하나를 고칠 때 전체 거래 수만큼 일합니다. 한 사람의 매매 기록이라 감당할 만한 크기로 봤습니다.

**홈의 투자 카드**에는 평가금액, 총 수익률, 이번 달 투자 계획 중 남은 돈(2번의 투자 가능 금액과 같은 식)이 나옵니다. 포트폴리오가 없으면 카드 자체가 뜨지 않습니다.

## 7. 반올림과 표기

| 대상 | 규칙 |
|---|---|
| 하루 예산, 기준 하루 예산 | 100원 단위 내림 |
| 하루에 모아야 할 돈 | 원 단위 올림 |
| 일평균, 카테고리 건당 평균, 절약액 | 원 단위 반올림 |
| 비율 (달성률, 증감률, 소비 비중, 저축률) | 소수 첫째 자리 반올림 |
| 보유 종목 수익률, 비중, 평균단가 | 소수 둘째 자리 반올림 (평가금액, 손익은 원 단위) |
| 문장 속 금액 | `Formats.won()`, 천 단위 쉼표 + "원" (예: 120,883,000원) |
| 문장 속 비율 | `Formats.rate()`, 끝자리 0은 뗌 (예: 37.3%, 30%) |
| 화면의 증감 색 | 오르면 빨강, 내리면 파랑 (국내 증권 앱 관례) |

## 8. 테스트로 잠근 것

[`TodayServiceTest`](../backend/src/test/java/com/stockflow/dashboard/service/TodayServiceTest.java)가 날짜를 고정한 시계로 1번 규칙을 확인합니다.

- 남은 생활비를 남은 날수로 나눈 것이 하루 예산이다 (100원 단위 내림 포함)
- 하루 예산을 넘기면 남은 돈은 0이고, 넘친 만큼을 따로 알려 준다
- 예산을 정하지 않았으면 남의 숫자를 채우지 않고 0을 돌려준다
- 이번 주는 월요일부터 일곱 날이고, 오늘 뒤는 아직 오지 않은 날이다

2~6번 규칙에는 아직 단위 테스트가 없습니다. 특히 평균단가(`Holding.buy()`/`sell()`)의 "전량 매도 후 재매수" 경우를 잠가 두는 것이 다음 순서입니다.
